# Отслеживание заказа: страница /track-order

## Что будет

Публичная страница отслеживания заказа по его номеру (первые 8 символов номера заказа, как он уже показывается в «Моих заказах», например `A3F91B2C`), с наглядным степпером этапов, датами, товарами и адресом доставки.

## Страница /track-order

- Заголовок «Отслеживание заказа» + краткая подсказка, где взять номер.
- Поле ввода номера (принимает и короткий номер из 8 символов, и полный) + кнопка «Найти». Enter тоже работает.
- Номер синхронизируется с URL: `/track-order?order=A3F91B2C` — при заходе по такой ссылке поиск выполняется автоматически.
- Результат — карточка заказа:
  - Номер заказа и дата оформления.
  - Текущий статус плашкой в существующих цветах статусов.
  - Степпер: Принят → Собирается → Отправлен → В пути → Доставлен. Выполненные этапы — галочка, текущий — активная точка с пульсацией, предстоящие — серые. Горизонтальный на десктопе, вертикальный на мобиле.
  - Дата под каждым пройденным этапом.
  - Отдельные состояния для отменённого и возвратного заказа (степпер останавливается, показывается плашка «Отменён» / «Возврат»).
  - Список товаров: фото, название, количество, цена; итог заказа и стоимость доставки.
  - Адрес доставки (частично скрыт: город/улица видны, номер дома и квартира замаскированы) и способ доставки, трек-номер и служба доставки, если продавец их указал.
  - Ожидаемая дата доставки: расчёт от даты отправки (или оформления) по способу доставки, с пометкой «ориентировочно».
- Если заказ не найден — карточка с сообщением «Заказ не найден, проверьте номер» и подсказкой войти в личный кабинет.
- Свои SEO-метаданные (title, description, og-теги).

## История статусов

Сейчас в базе истории статусов нет — даты этапов будут собираться из уже имеющихся полей заказа (дата оформления, отправки, получения, возврата). Дополнительно добавим таблицу истории изменений статусов: она автоматически пополняется при каждой смене статуса позиции заказа, и как только записи появятся, страница показывает точные даты и подробную ленту событий вместо расчётных.

## Личный кабинет и навигация

- В списке заказов в `/account` — кнопка «Отследить» на каждой карточке заказа (рядом с «Подробнее»), ведёт на `/track-order?order=НОМЕР`; клик по ней не открывает модалку деталей.
- Такая же кнопка в модалке деталей заказа.
- Ссылка «Отследить заказ» в футере в блоке «Покупателям» и в меню личного кабинета покупателя (боковое меню/навигация покупателя).

## Дизайн

Только существующие семантические токены темы (brand/foreground/muted/card, плашки статусов из текущей палитры), шрифты и радиусы как на остальных страницах, плавные переходы `ui-transition`. Иконки — lucide (Check, Package, Truck, MapPin, CheckCircle2).

## Технические детали

- Новый роут `src/routes/track-order.tsx` — публичный (SSR), search-параметр `order` валидируется.
- Новая серверная функция `getOrderTracking` в `src/lib/tracking.functions.ts` (без авторизации, публичная): нормализует введённый номер, ищет заказ по префиксу id, возвращает только безопасный DTO — короткий номер, статус, даты этапов, товары (название/фото/цена/кол-во), способ доставки, замаскированный адрес, трек-номер, ожидаемую дату. Никаких телефонов, e-mail, id покупателя и продавца.
- Стадии считаются из статусов позиций заказа через существующую логику `src/lib/order-status.ts` (агрегация как в `/account`), маппинг на 5 витринных этапов.
- Миграция: таблица `order_status_history` (позиция заказа, старый/новый статус, дата) + триггер на смену статуса позиции, RLS — читать может покупатель заказа и продавец позиции, вставка только триггером; чтение для страницы идёт через серверную функцию.
- Компонент степпера `src/components/tracking/OrderStepper.tsx` — переиспользуемый.
- Правки: `src/components/AppLayout.tsx` (футер), навигация покупателя, `src/routes/_authenticated/account.tsx` (кнопки «Отследить»).
